# 来週の準備（準備ボード）

来週の予定を1件ずつ見て、準備が要るものを洗い出し、AIが作れるものは作り切る。本人がやることは「判断・発言・送信・最終確認」に絞り、他の人への依頼は送れる文面つきで用意する。最後に1枚の準備ボード（HTML）にまとめて渡す。

## 最初に確認すること

- このフォルダに `my-profile.md` があるか。**なければ [references/setup.md](references/setup.md) のセットアップを先にやる**（使えるツールの確認・本人への質問・呼び方と口調の確認）。終わったら、そのまま初回の準備に進んでよいか本人に聞く
- `my-profile.md` があれば読み、書かれた情報源・呼び方・口調・出力先・資料の形式に従う。前回から変わったこと（新しくつないだツールなど）があれば、本人の了承を得て更新する

## 完成条件

1. 来週（月〜金。本人が指定すれば土日の仕事の予定も）の予定を全件読み、件数と、取れなかった範囲を控えた
2. 予定ごとに状態を1つ付けた：`ready` 準備済み／`made` AIが作った／`you` 本人が動く／`ask` 他の人に依頼
3. 未準備で材料がそろうものは、作り切ってファイルにした（送信・公開はしていない）
4. 依頼は、宛先・手段・送る時・期限・お願いすること・全文がそろっている
5. 来週の重点アクションごとに、山場・見込み・詰まりどころを書いた
6. 「任せる範囲を広げる提案」を、今すぐやれること／情報があればできること／権限があればできることの3列で書いた
7. 準備ボードを作ってブラウザで開き、最終メッセージで、ボードの場所・最初にやること・決めてほしいことを渡した

## 守ること

- **メール・チャットの送信、投稿、予定の作成・変更・削除、外部への公開はしない。** 作るのは文面・資料・下書きファイル・準備ボードまで。本人が `my-profile.md` で明示的に許可した操作（例：会議室の予約、Outlookの下書き作成）だけは、その範囲で行い、何をしたかをボードに書く
- 読むのは本人がアクセスできる情報だけ。取れなかった情報を「なし」と扱わず、ボードの末尾と最終メッセージに「取れなかった範囲」として書く
- 記録にない決定を作らない。推測には「要確認」を付ける。数字や表記が資料ごとに違う時は、両方と出典を書き、どちらが最新かを本人に聞く
- 対人の文面は、受け手にどう聞こえるかを見てから載せる。詰めているように聞こえる言い方は、「私の方で外せるものはありますか？」のような形に直す。メンバー同士を比べない
- 本人の役割（`my-profile.md` の「自分がやること・任せること」）に沿って仕分ける。人に任せるべき作業を本人の欄に入れない
- 社外の人の個人情報（電話番号など）は、ボードや文面に必要以上に書き写さない

## 手順

### 1. 集める

[references/collect.md](references/collect.md) の表を `my-profile.md` の情報源に当てはめて集める。独立した取得はまとめて並列に行う。最初に「予定◯件、チャット◯件、メール◯件、取れなかった範囲」を控え、ボードの冒頭文と最終メッセージに使う。

来週の重点アクションは、`my-profile.md` の置き場所（週報のファイル・チャネルなど）から読む。見つからなければ、本人に「来週の重点を3つまで」聞く。返事を待つ間も、予定の読み込みは進めてよい。

### 2. 仕分ける

[references/classify-and-make.md](references/classify-and-make.md) の基準で、予定ごとに目的・状態・本人の一手・他の人・使うもの・重なりを決める。重点アクションの見込み（`green`＝いける／`amber`＝一部持ち越し・要注意）もここで出す。根拠のない楽観は `amber` にする。

### 3. 作り切る

同じファイルの「作り方の型」に沿って、期限が近いもの、本人の判断や社外が絡むものから作る。資料の形式は `my-profile.md` に従う（指定がなければMarkdown）。PowerPointなどを作れるスキルや道具がこの環境にあれば使ってよい。
材料が足りずに作れないものは無理に埋めず、「情報があればできること」に回す。

### 4. 依頼文をそろえる

宛先ごとに1本。社内と社外に分け、送る時・期限・お願いすることを1行で添える。**呼びかけと口調は `my-profile.md` の「呼び方と口調」の表どおりにする。** 本人が埋める箇所だけ【　】にする。社外宛てには「送る前に確認」と書く。同じ文面を `02_送る文面集.md` にも残す。

### 5. 任せる範囲を広げる提案

今回止まったこと、推測で埋めたこと、AIがもっと先まで進められることを3列にする。提案は「必要なもの → できるようになること → 効く場面・相談先」の形で、具体的に書く（例：「会議の文字起こしを読める設定があれば、議事録とネクストアクションを自動で作れる」）。

### 6. ボードを作って開く

1. [references/board-data.md](references/board-data.md) の形で、出力先に `board-data.json` を書く。見本は [assets/sample-board-data.json](assets/sample-board-data.json)
2. このスキルのフォルダにある `scripts/build_board.py` を、`python <スキルのフォルダ>/scripts/build_board.py <出力先>/board-data.json --open` のように実行する（標準ライブラリだけで動く。`python` がなければ `python3`）。ERRORは直して再実行し、WARNの【】は最終メッセージで伝える
3. Pythonが使えない環境では、`assets/board-template.html` の `__TITLE__` をボードのタイトルに、`__DATA__` を board-data.json の中身（`</` は `<\/` に置き換える）に差し替えて `準備ボード.html` を書き出し、ブラウザで開く

### 7. 渡す

最終メッセージは短く、次の順にする。

1. ボードの場所（1行）
2. 今夜〜月曜の朝にやること（上から順に3〜6件、理由を一言）
3. 重点アクションの見込み（1行ずつ）
4. 決めてほしいこと・【】の箇所
5. 取れなかった情報と、任せる範囲を広げる提案で一番効くもの

本人が文面や呼び方を直したら、`my-profile.md` の「呼び方と口調」に反映してよいか聞き、了承を得て更新する（次の週から同じ間違いをしない）。

## 出力フォルダ

既定は `my-profile.md` の出力先（未設定なら、作業中のフォルダの `week-prep-output/`）の下に `YYYYMMDD/`（来週の月曜の日付）。

| ファイル | 中身 |
|---|---|
| `01_週間準備パック.md` | 先に決めてほしいこと、日ごとの予定と状態、会議ごとの話すこと・決めること |
| `02_送る文面集.md` | 依頼文の全文（D1〜） |
| `03_…` 以降 | 資料・アジェンダ・台本など、その週に作ったもの |
| `board-data.json` | ボードのデータ |
| `準備ボード.html` | ブラウザで開くボード |
