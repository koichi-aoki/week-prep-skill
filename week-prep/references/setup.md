# 初回セットアップ

`my-profile.md` がない時に1回だけ行う。目的は、この人の会社のツールと、この人の言葉づかいに合わせること。質問は1回にまとめ、答えを待つ間にできる確認は先に進める。最後に `my-profile.md` を書いて本人に見せる。

## 1. 使えるツールを確かめる

このセッションで使えるツール（コネクタ・MCPサーバー・ローカルのファイル）を確認し、次の情報ごとに「どこから取れるか」を対応させる。ツールの一覧に出ていないものは、使えると決めつけない。名前が分からない時は、ツール検索で `calendar` `mail` `chat` `slack` `teams` `drive` `sharepoint` `notion` などを探す。

| 情報 | よくある取得元 |
|---|---|
| 予定 | Outlookの予定表（Microsoft 365）、Googleカレンダー |
| チャット | Teams、Slack、Google Chat |
| メール | Outlook、Gmail |
| 資料・ファイル | SharePoint・OneDrive、Googleドライブ、Box、ローカルのフォルダ |
| 会議の記録 | 議事録のフォルダ、会議の文字起こし、Notionなどの会議ノート |
| タスク・案件 | Notion、Asana、Backlog、Jira、スプレッドシート |
| 顧客・商談 | Salesforce、HubSpotなどのCRM、商談メモのフォルダ |
| 週報・目標 | 週報のファイル・チャネル、目標管理のページ |

- 取れる情報源ごとに、**読み取りだけで小さく試す**（例：明日の予定を1件、直近のメールを1件）。書き込み系の操作は試さない
- 予定がどこからも取れない場合は、本人に「来週の予定を貼り付ける」か「カレンダーを書き出したファイル（.ics・CSV）を置く」方法を案内する
- つながっていないツールがあれば、本人に「claude.aiのコネクタ設定でつなぐ」「`claude mcp add` でMCPサーバーを追加する」方法があることを伝える。会社のツールをAIにつなぐ前に、社内のAI利用のルールを確認するよう添える。つなぐかどうかは本人が決める

## 2. 本人に聞く（1回にまとめる）

分かっていることは聞かない。ツールから読める情報（名前・部署など）は先に読み、確認の形で聞く。

1. ボードでの呼び方（例：「山田さん」「あなた」）と、役割・立場
2. 自分がやるべき仕事と、人に任せたい仕事（任せる相手がいれば、その人の担当も）
3. 来週の重点アクションの置き場所（週報のファイル・チャネル・ページ）。なければ、毎回3つまで教えてもらう形でよいか
4. 準備を作るタイミング（例：金曜の夕方、週報を書いたあと）
5. 資料の形式（Markdown／PowerPoint／Googleスライド用の下書き など）と、社内テンプレートの場所
6. 会議室・フォンブースの予約の仕方（予約できるツールがあるか。AIに予約まで任せるか、予約リストを作るだけにするか）
7. 出力先のフォルダ（既定：作業中のフォルダの `week-prep-output/`）

## 3. 呼び方と口調を学ぶ（本人の了承を得てから）

依頼文を「本人が書いたのと見分けがつかない」ものにするための確認。

1. 本人の了承を得て、本人が**送った**チャットとメールを直近2〜4週間ぶん読む
2. 相手ごとの呼びかけ（例：「◯◯さん」ではなく下の名前・あだ名で呼んでいる）、社内チャットの語尾・絵文字の使い方、社外メールの書き出し・結び・署名を拾う
3. 表にして本人に見せ、直してもらう。**メッセージの本文そのものは `my-profile.md` に写さない**（呼び方と口調の特徴だけを残す）

## 4. my-profile.md を書く

[../assets/profile-template.md](../assets/profile-template.md) を写して、このスキルのフォルダに `my-profile.md` として保存する。分からない欄は空けたままにし、「未設定」と書く。書いたら本人に要点を見せる。

## 5. 最初の1回

「このまま来週の準備をしてみますか？」と聞き、OKなら SKILL.md の手順1から進める。1回目のボードを見てもらい、直したいところ（呼び方・仕分けの基準・資料の形式）を `my-profile.md` に反映する。
