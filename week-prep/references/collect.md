# 集める（手順1）

対象は来週の月曜0:00〜金曜23:59（本人のタイムゾーン）。本人が指定すれば土日の仕事の予定も含める。翌々週の頭に締切がある準備も拾う。
取得元は `my-profile.md` の「情報源」に従う。独立した取得はまとめて並列に行う。APIが混み合いのエラー（429など）を返したら、示された待ち時間に従い、待つ間に別の確認を進める。

## 取るもの

| 情報 | 見るところ | 取り方のコツ |
|---|---|---|
| 来週の予定 | 件名・時刻・主催者・出席者・場所・本文・オンライン会議か | 件数が多いので、日を分けて取ると漏れにくい。**時刻がUTCで返るツールが多いので、本人のタイムゾーンに直す**。仮の予定（tentative）は仮と分かるようにする |
| 来週の重点アクション | 週報の「来週の重点」、目標のページ | 置き場所は `my-profile.md`。なければ本人に聞く |
| 会議の記録 | 直近1〜2週間の議事録・文字起こし・会議ノート | 決まったこと・宿題（担当・期限）。来週の前提を変えるもの（数字の確定、時刻の変更） |
| 本人あてのチャット | 直近4〜7日 | 依頼・質問・未返信 |
| 本人が送ったチャット | 直近4〜7日 | 本人が約束したこと（「月曜にやります」など） |
| 予定ごとのやりとり | 会社名・人名・会議名でチャットとメールを検索し、関係するスレッドを読む | 準備物のありか、担当、変更 |
| メール | 直近7日。社外の予定は会社名・人名で検索 | 返信待ち・期限・先方からの依頼・招待の有無 |
| 資料・ファイル | 予定の名前・会社名で検索。直近に作られた資料 | すでにある資料・テンプレート・前回の提案書 |
| 顧客・商談 | CRMやメモにある前回の商談の結果 | 先方が気にしていたこと、こちらが約束したこと、次のステップ |
| タスク | 来週が期限のタスク | 誰の仕事か |

## 拾い漏れを防ぐ確認

- 同じ時間帯に2件以上ある予定（重なり）は全部拾い、どちらを優先するかと連絡文を用意する
- 社外の打ち合わせなのに出席者に社外の人がいない予定は、招待が届いていない可能性がある。承諾のメールがあるかまで確かめる
- 社外の方とのオンライン会議で、オフィスにいる時間帯のものは、会議室・フォンブースが要るかを見る
- 本人が主催の定例は、欠席・お休み・代理の進行を本人が決められる
- 祝日・休暇の日に残っている定例がないか
- 数字が資料ごとに違う時は、日付の新しい方と出典を控える
- 本人が約束したのに、まだやっていないこと（送っていない依頼など）がないか

## 取れなかった時

- 取れなかった情報源と理由（つながっていない・権限がない・設定で無効）を控え、ボードの `footer` と最終メッセージに書く
- 取れなかったことで推測にした箇所には「要確認」を付ける
- つなげば次から取れるものは、「任せる範囲を広げる提案」の「権限・設定があれば」の列に入れる
